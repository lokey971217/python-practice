# 基础版实验室知识库 RAG 问答系统

## 项目简介

这是一个使用 Python、简单文本检索和 DeepSeek API 实现的最小可运行 RAG（检索增强生成）学习项目。项目没有使用向量数据库、Embedding 或 LangChain，而是通过容易理解的字符重合评分，完整演示“先检索、再让大模型基于资料回答”的基础链路。

本项目用于学习复盘和面试展示，不是生产级系统。知识库中的实验室名称、规定和联系方式均为虚构内容，只用于程序测试。

## 项目解决的问题

普通大模型不了解本地实验室的具体规定，直接提问时可能不知道答案或产生编造。本程序先从本地知识库检索与问题最相关的内容，再把用户问题和检索结果一起交给 DeepSeek，并通过系统提示词要求模型只能根据知识片段回答。当片段中没有答案时，模型应明确说明知识库中没有相关信息。

## 核心功能

- 从 UTF-8 编码的文本文件加载本地知识库；
- 按空行把知识库切分为多个独立片段；
- 用问题与片段的字符重合数量计算相关性；
- 遍历片段并检索得分最高的一个片段；
- 将用户问题和检索片段组合成增强后的 Prompt；
- 通过 OpenAI Python SDK 的兼容接口调用 DeepSeek；
- 捕获模型调用异常，避免程序因接口错误直接崩溃；
- 使用 `unittest` 验证知识切片、最佳片段检索和相关性评分。

## RAG 工作流程

```text
用户问题
  → 知识库切片
  → 相关性评分
  → 检索最佳片段
  → 问题与知识片段组成 Prompt
  → DeepSeek 生成答案
  → 输出知识来源和最终答案
```

## 核心代码设计

### `load_knowledge()`

- 输入：无显式参数，读取当前项目目录中的 `knowledge.txt`。
- 处理：以 UTF-8 编码打开文件并读取全部文字。
- 返回值：一个包含完整知识库内容的字符串。

### `split_knowledge()`

- 输入：完整的知识库字符串 `text`。
- 处理：按连续两个换行符，也就是空行，切分文字；再清理片段首尾空白并过滤空片段。
- 返回值：知识片段组成的字符串列表。

### `calculate_score()`

- 输入：用户问题 `question` 和一个知识片段 `chunk`。
- 处理：把问题中的字符去重，统计有多少个非空白字符也出现在知识片段中。
- 返回值：整数相关性分数。分数越高，只代表字符重合越多，不代表真正理解了语义。

### `retrieve_best_chunk()`

- 输入：用户问题 `question` 和知识片段列表 `chunks`。
- 处理：逐个调用 `calculate_score()`，记录当前得分最高的片段。
- 返回值：得分最高的一个知识片段；如果列表为空，则返回空字符串。

### `generate_answer()`

- 输入：用户问题 `question` 和检索到的知识片段 `context`。
- 处理：从环境变量读取 `DEEPSEEK_API_KEY`，创建 DeepSeek 兼容客户端，把系统提示词、知识片段和问题发送给 `deepseek-v4-flash`。系统提示词要求模型只根据给定片段回答，资料不足时明确说明。接口调用包含在 `try/except` 中。
- 返回值：成功时返回模型答案；失败时返回便于定位问题的错误信息。

### `main()`

- 输入：通过终端 `input()` 获取用户问题。
- 处理：依次完成知识加载、切片、最佳片段检索和模型问答，并打印检索来源。
- 返回值：无。它负责组织程序执行流程。`if __name__ == "__main__":` 保证导入模块进行测试时不会启动交互输入。

## 环境配置（Windows PowerShell）

在 `projects/rag_basics` 目录中执行：

```powershell
# 创建虚拟环境
python -m venv .venv

# 只在当前 PowerShell 进程临时放宽脚本执行策略
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 激活虚拟环境
.\.venv\Scripts\Activate.ps1

# 安装项目依赖
python -m pip install -r requirements.txt
```

只在当前 PowerShell 窗口临时设置 API Key，关闭窗口后该变量失效：

```powershell
$env:DEEPSEEK_API_KEY = "在此粘贴你自己的 API Key"
```

安全地确认变量是否已设置，而不显示 Key 内容：

```powershell
if ($env:DEEPSEEK_API_KEY) { "DEEPSEEK_API_KEY 已设置" } else { "DEEPSEEK_API_KEY 未设置" }
```

不要把真实 Key 写入源码、README、`.env` 或 Git 提交记录。

## 面试讲解稿（约 1 分钟）

这个项目是我从零手写和逐步调试的基础版 RAG 问答系统，目的是理解 RAG 最核心的工作链路。程序先读取本地实验室知识库，按空行切成多个片段，再用字符重合分数找出和用户问题最相关的片段。之后，我把问题和检索结果一起发送给 DeepSeek，并通过系统提示词限制模型只能根据资料回答，从而减少编造。在工程实践方面，我使用环境变量保护 API Key，用 `try/except` 处理接口异常，还编写了 3 个 `unittest` 测试来验证切片、检索结果和相关性评分。我知道它目前只是原理学习项目，字符重合不等于语义理解，也没有向量数据库和 Top-K 检索；下一步我会在保留这条基础链路的前提下学习 Embedding 和语义检索。

## 当前局限

- 当前检索依据字符重合，不是真正的语义检索；
- 每次只返回一个最佳片段，没有 Top-K 结果；
- 本地知识库规模较小，尚未验证大规模文本场景；
- 没有使用向量数据库；
- 对无关问题也可能选中一个表面上字符相似的片段；
- 当前项目主要用于理解 RAG 原理，不应描述为生产级系统。

## 下一步计划

1. 学习 Embedding，把问题和知识片段转换为语义向量；
2. 使用余弦相似度比较向量相关性；
3. 实现 Top-K 检索，一次返回多个相关片段；
4. 增加相似度阈值，对明显无关的问题拒绝检索结果；
5. 在理解本地向量检索后，再学习合适的向量数据库；
6. 在答案中标明引用的知识片段来源；

8. 将稳定的 RAG 能力接入后续 Agent 学习项目。
